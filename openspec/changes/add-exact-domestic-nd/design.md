# Design and primary rules

The current official 99-page annex (SHA256 `6e093226b29b38c5c8de825f70c1b1cb8ed81e2f4a6eb0b3ff52708fc1eb2769`) pages 57–58 makes ND reference mandatory and requires correspondence of original informative data; Nota 9/p. 73 identifies code02 as amount correction. The native ND XSD lines 880–946 requires1..10 references but has weaker optional reference fields/reason bounds and an older annotation calling02 text correction. Keep official bytes unchanged; the named case requires one explicit FE 01/reference 02 tuple and reason3–180 Unicode characters under the current annex. Page56 requires positive supplied payment allocations and exact total reconciliation, independently of whether cash was received.

`ExactNdInputSchema` contains an unchanged current exact ordinary FE source, a new ND02 identity/emission, explicit `adjustments[{originalLineNumber,line}]`, independent payment allocation and one reference. The reference's original clave/emission lexeme must agree exactly; declared ND chronology uses the existing full-fraction instant comparator. Every original line is selected at most once in this deliberately bounded case, and output line numbers follow caller order sequentially. Preserve original CABYS, classification, unit/commercial/transaction metadata; quantity, price, description and ordinary discounts are explicit incremental source facts. Do not derive an increment from the original total, impose a guessed ceiling or mutate source facts.

The calculator checks original FE identity/current ordinary math, new ND identity and the independent delta using the reviewed shared monetary kernel. Header parties/currency and applicable original condition/terms remain immutable; no new override object can substitute them. Unsupported source-family/foreign/special cases reject. Source math cannot prove acceptance, ownership, cumulative account state or legal eligibility. The actual ten-year issuance/submission-time rule remains a mandatory caller trusted-time gate with unresolved boundary policy; no hidden Date.now, guessed equality/leap-day rule or new signing authority is added. Existing FE/TE/NC/current/retained and Number APIs remain unchanged; no retained ND XML/signing/POST builder.
