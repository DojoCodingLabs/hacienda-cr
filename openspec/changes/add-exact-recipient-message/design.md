Base: SDK main a1e0e1c64b6abc3a68ad324d512843a6d65dd82e, packages still0.9.0.

[Official current annex](https://www.hacienda.go.cr/docs/ANEXOS_Y_ESTRUCTURAS_V4.4.pdf),
SHA256 `6e093226b29b38c5c8de825f70c1b1cb8ed81e2f4a6eb0b3ff52708fc1eb2769`,
printed pages61–62 and81 (note18), binds source seller/buyer, original full tax and
total, confirmation date, message codes and optional explicit VAT decisions.
Reason is required for partial/rejected,5–160 Unicode characters. Proportionality
must omit activity. Preserve every official XSD byte and its narrower numeric
buyer identity instead of stripping letters.

The strict input contains immutable original exact FE facts, confirmation time,
actual buyer consecutive and message/reason. It admits no edited total, proof
boolean or counterparty override. Recalculate original source with the existing
exact kernel. Explicit reviewed tax allocations are decimal strings bounded by
source amounts; they confer no actual tax entitlement. The first rejection case
has no tax-allocation object. Other original regimes are required future work.

Keep legacy public Number signature/serialization unchanged; share only internal
ordered field projection. No exact-to-Number conversions or retained XML builder.

[Official API](https://www.hacienda.go.cr/docs/ComprobantesElectronicosAPI.html)
requires consecutivoReceptor for confirmation POST;201 remains pending validation.
It documents GET by original50-character clave. MensajeHacienda XSD lacks the
receiver consecutive. Thus an authentic response to the original FE cannot by
itself establish this confirmation outcome. Do not invent a composite status
route, reinterpret seller/buyer HTTP roles, or treat generic getStatus as an
ambiguous-message recovery oracle. Independent primary/operational evidence is
required before implementing those paths. No network, publication or activation.

The actual buyer signer, institutional original acceptance, immutable material,
current authorization, durable sequence, legal ten-year calendar and applicable
submission window remain external gates. Source chronology uses full declared
fractions/offsets; it does not invent a wall-clock or leap-day legal oracle.

An explicit positive credit outside proportionality requires the actual receiver
activity (annex p.62). If supplied, condition01 credit equals the full original
tax: note18/footnote47 expressly defines all paid IVA used as credit. Omission
does not invent a credit amount or prove eligibility. Condition04 cannot declare
a positive credit.
